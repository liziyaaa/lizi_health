# 配置与数据规范

这是待实现的 V1 数据契约，不是已运行快捷指令的输出保证。`config.example.json` 仅供人或后续构建工具参考，目前没有程序自动加载它。

## 日期与窗口

使用设备本地日历计算日期，不能用「当前时间减去 24 小时」代替昨天 00:00。跨夏令时或旅行时，两者可能不同。日期输出为带时区偏移的 ISO 8601；时区标识无法读取时，保留偏移并记录该限制。

| 数据 | 拟定窗口 | 选择与归属 |
| --- | --- | --- |
| 心率 | 昨天 00:00 至今天 00:00 | 开始时间位于半开区间 `[start, end)` |
| 步数 | 昨天 00:00 至今天 00:00 | 选取与窗口重叠的区间，保留完整原始样本 |
| 睡眠 | 昨天 18:00 至今天 12:00 | 选取与窗口重叠的区间，实际截止不晚于运行时刻 |

`report_date` 是前一个本地日历日。睡眠窗口覆盖当晚至次日早晨，心率与步数覆盖该日期全天，不能把这三类数据误称为完全相同的时间范围。V1 睡眠窗口不覆盖全部午睡，也不适合所有倒班作息；有这类需要时应调整设计。

早上 09:00 运行时，睡眠 `planned_end` 可以是 12:00，`end` 必须是 09:00，并标记 `window_complete: false`。即使计划窗口已结束，也不能仅凭时间认定手环数据已经同步齐全。

## 样本结构

| 类别 | 字段 | 单位或含义 |
| --- | --- | --- |
| 所有样本 | `start`, `end`, `source` | ISO 8601 起止时间；设备上观察到的来源名称 |
| 睡眠 | `stage_raw` | 保留实际返回的类别值或本地化文字，不凭空映射 |
| 心率 | `bpm` | 数值，次/分钟 |
| 步数 | `count` | 数值，步 |

来源或阶段不能从动作读取时，使用 `null` 并记录在 `warnings`；不能把所有来源都硬编码成「小米手环 8」。示例中的 `Mi Fitness (example)` 是虚构标签，不用于自动匹配。

## 去重与统计

- 睡眠中的「在床上」和各睡眠阶段可能重叠，不能合计。统计实际睡眠应先按来源处理重叠区间，再选择真正睡眠阶段。
- 步数的来源筛选或样本求和不等于 Apple 健康按来源优先级得到的汇总。跨午夜样本也不能假装全部属于一天，或按持续时间均摊而不注明估算。
- V1 只保存原始样本，不输出未经验证的平均心率、总睡眠或已去重总步数。后续统计需要定义算法和验证。
- 无样本返回空数组。记录查询状态与警告；不要把无数据、拒绝权限和零值混为一谈。

## JSON 生成

使用字典和对象数组构造 JSON，日期先格式化为文本，数值保留为数字。不能直接拼接未经转义的来源文本，也不能将字典的显示摘要冒充 JSON。

如果当前设备只能方便地取得分隔文本，应明确使用另一个 `raw-text` 版本；不能在 `schema_version: 1.0` 下把数组悄悄换成字符串。序列化后必须实际解析文件验收。

## 与原始设计的差异

`design/original/` 和原 ZIP 原样保留。新的建议配置将首次邮件编写表单设为开启，明确睡眠实际截止时间，并补充了来源筛选、日期归属和未知值处理。原配置中的 `show_compose_sheet: false` 不应未经首轮检查就照搬。
