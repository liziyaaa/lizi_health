# 后续开发任务

## 已有基础

原设计包、参考配置、JSON 样本结构、分段搭建路线和验收清单。本仓库没有源程序、编译器依赖、构建脚本或运行测试结果。

## 按顺序实施

1. 在 iPhone 上建立最小查询，确认当前 iOS 的健康动作参数、可用属性、来源过滤及 JSON 序列化方式。
2. 用自己建立的最小快捷指令核对动作格式，再实现睡眠、心率、步数与文件保存。不要猜动作内部参数后声称可运行。
3. 调研 Windows 可用的生成工具，固定版本和依赖，提供可重复执行的构建命令。生成物先标记为未签名。
4. 核对 Apple 支持的签名与分享流程；独立验证第三方方案的当前可用性、费用与数据处理方式。
5. 发布经过签名的文件或真实 iCloud 分享链接前，使用 iPhone 完成导入、授权、采集、文件保存和邮件验收。
6. 最后测试定时触发和锁屏运行，并记录版本、已知限制和错误处理。

## 签名边界

Apple 官方文档提供 macOS 的 `shortcuts sign` 路径。当前项目没有 macOS 环境，也没有完成其他签名路径。

候选工具：

- [shortcut-cli](https://github.com/Wuvomi/shortcut-cli)
- [shortcut-signer](https://github.com/wynx1123/shortcut-signer)

它们是调研入口，尚未作为本项目依赖。第三方服务是否免费、是否需要账户、是否支持当前格式，都需要实际验证。不要向签名服务上传健康记录、收件人或凭据；分享模板应使用设备端配置。

仅生成 plist 或重命名为 `.shortcut`，不能作为成功导入的证据。不能在 README 中添加猜测的 iCloud 安装链接。

## 完成定义

- 源文件和构建步骤齐全，可在记录的工具版本上重复构建。
- 已签名的产物可被 iPhone 实际导入。
- 首次运行在设备端配置地址并预览邮件。
- JSON 与健康记录抽样一致，边界、重复来源和空数据处理通过验收。
- 保存和发信完成实测；定时与锁屏限制如实记录。
- 分享模板没有真实健康数据、邮箱地址或账户密钥。

此前的聊天构思不应当成实测记录。健康统计与 AI 报告属于后续功能，不应因原始数据导出完成就宣称已经实现。
