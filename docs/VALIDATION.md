# 验收清单

当前各项均未进行 iPhone 实机验证。建议先手动执行，再测试定时执行；记录 iOS、Mi Fitness 版本、数据来源和测试时间。

| 检查 | 通过标准 |
| --- | --- |
| 健康权限 | 三类查询可读取；拒绝权限或无样本有明确提示，不生成假零值 |
| 数据来源 | 与 Apple 健康实际来源一致；无法读取来源时标记未知 |
| 日期边界 | 昨天 00:00 / 今天 00:00 为本地日历边界，时间戳保留偏移 |
| 跨午夜睡眠 | 完整保留重叠样本，计划截止与实际截止分别记录 |
| 睡眠类别 | 保留原类别；不将「在床上」与阶段叠加 |
| 心率 | 时间、数值和 bpm 单位与健康记录抽样一致 |
| 步数 | 保留来源；不简单把多个设备的样本相加当作去重总数 |
| 空数据 | 返回空数组与查询状态，说明没有样本的可能原因 |
| JSON | 可解析，数组与数字类型正确，引号、换行和中文来源不破坏结构 |
| 文件 | iCloud 路径正确，同日重复运行行为明确 |
| 邮件 | 首轮预览地址；收到真实 JSON 附件，附件内容与保存文件一致 |
| 自动发送 | 自己启用后实际收到邮件；失败时不声称发送成功 |
| 定时运行 | 在设备上单独创建触发，核对时间与日报日期 |
| 后台条件 | 分别记录锁屏、重启后、断网的执行结果；失败可定位到动作 |
| 延迟同步 | 补同步后重跑会更新文件；不会把旧数据宣称为最新 |

Windows 可先检查示例 JSON 语法（这不验证快捷指令）：

```powershell
py -m json.tool examples/health_example.json
```

实际报告若保存于电脑，也可用同一命令解析，但不要上传它到 GitHub。反馈问题时使用虚构内容，或只提供报错文字和已脱敏的动作截图。
